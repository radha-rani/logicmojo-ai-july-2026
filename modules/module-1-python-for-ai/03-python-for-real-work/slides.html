OOP · 1 of 6A class is a blueprint; an object is built from it

class Account:
    def __init__(self, balance):    # runs at creation
        self.balance = balance      # attribute

    def deposit(self, amount):      # instance method
        self.balance += amount

a = Account(100)
a.deposit(50)
print(a.balance)   # 150
  • The class is the design; an object is one thing made from it.
  • __init__ sets up the starting attributes.
  • Methods are its actions.
  • self is this object, passed in automatically.
Think of it asA cookie cutter (class) and the cookies (objects).

OOP · 2 of 6Each object holds its own state

a = Account(100)
b = Account(0)
a.deposit(50)

print(a.balance, b.balance)   # 150 0
print(type(a))   # <class '__main__.Account'>
  • Two objects from one class are independent: changing a does not touch b.
  • a is an object (instance) of Account.
  • type(a) shows which class it is.

OOP · 3 of 6Instance, class, and static methods

class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    def describe(self):                # instance method
        return f"{self.celsius}C"

    @classmethod
    def from_fahrenheit(cls, f):       # class method: alternate constructor
        return cls((f - 32) * 5 / 9)

    @staticmethod
    def is_freezing(celsius):          # static method: plain helper
        return celsius <= 0

t = Temperature.from_fahrenheit(212)
print(t.describe())            # 100.0C
print(Temperature.is_freezing(-4))   # True
  • Instance method takes self: it works on one object.
  • Class method takes cls: here an alternate constructor. from_fahrenheit(212) builds a Temperature from a Fahrenheit reading.
  • Static method takes neither: a plain helper that belongs with the class, like is_freezing(-4).

OOP · 4 of 6Inheritance: reuse and extend

class Account:
    def __init__(self, balance):
        self.balance = balance
    def summary(self):
        return f"balance {self.balance}"

class SavingsAccount(Account):
    def __init__(self, balance, rate):
        super().__init__(balance)   # reuse the parent
        self.rate = rate
    def summary(self):              # override
        return f"balance {self.balance}, rate {self.rate}"
  • A subclass reuses a parent and adds to it.
  • super() calls the parent's version, so you do not repeat it.
  • Override a method to change the behavior.

OOP · 5 of 6Polymorphism: same call, different behavior

for acc in [Account(100), SavingsAccount(100, 0.05)]:
    print(acc.summary())

# balance 100
# balance 100, rate 0.05
  • The same method name, summary(), runs different code depending on the object.
  • The caller does not need to know the exact type; it just calls the method.
  • This is duck typing: if it has the method, it works.

OOP · 6 of 6Multiple inheritance and the MRO

class Walk:
    def move(self): return "walking"
class Swim:
    def move(self): return "swimming"

class Amphibian(Walk, Swim):
    pass

a = Amphibian()
print(a.move())   # walking  (Walk comes first)
print([c.__name__ for c in Amphibian.__mro__])
# ['Amphibian', 'Walk', 'Swim', 'object']
Use sparingly A class can inherit from more than one parent. When both define the same method, Python follows the method resolution order (MRO), left to right. It gets subtle fast, so prefer single inheritance or small, focused mixins.

Errors · 1 of 2Catch each failure by name

def ratio(text):
    try:
        a, b = text.split("/")
        return int(a) / int(b)
    except ValueError:          # split gave the wrong count, or int() failed
        return "need two integers like 3/4"
    except ZeroDivisionError:   # b was 0
        return "cannot divide by zero"

# group errors that share a response
try:
    risky()
except (KeyError, IndexError):
    print("something was missing")
  • try runs the risky code; each except handles one kind of failure.
  • Python runs the first matching block, so list the specific errors before the general ones.
  • Group errors that deserve the same response with a tuple: except (A, B):.
Name what you expect A bare except: swallows every error, including typos and bugs. Catch the exceptions you expect and let the rest surface.

Errors · 2 of 2else and finally: the full shape

def read_int(text):
    try:
        n = int(text)          # the risky step only
    except ValueError:
        print("not a number")
        return None
    else:
        print("parsed cleanly")   # runs only if try raised nothing
        return n
    finally:
        print("attempt finished")  # always runs, error or not
  • else runs only when the try block raised nothing. Keep just the risky line in try and the follow-up work in else, so you never catch an error you did not mean to.
  • finally runs no matter what: success, handled error, even an error on the way out. It is where cleanup goes, like closing a file or a connection.

Files · 1 of 2Text files: just strings on disk

with open("notes.txt", "w") as f:  # "w" overwrites
    f.write("first line\n")
    f.write("second line\n")

with open("notes.txt") as f:       # default mode is read
    whole = f.read()               # entire file as one string

with open("notes.txt") as f:
    for line in f:                 # one line at a time
        print(line.strip())        # drop the trailing newline
  • with open(...) opens the file and closes it for you, even if an error is raised.
  • Mode picks the intent: "r" read (default), "w" overwrite, "a" append.
  • .read() gives the whole file; looping gives it line by line, which scales to large files.
  • A text file is only characters. Any structure is on you to parse, which is why the next slide reaches for JSON.

Files · 2 of 2JSON: structure that survives the round trip

import json

with open("data.json", "w") as f:
    json.dump({"classes": 45}, f)

with open("data.json") as f:
    data = json.load(f)     # back to a real dict
print(data["classes"])      # 45  (an int, not "45")
  • When the data has structure (nested keys, lists, numbers), save it as JSON instead of hand-formatted text.
  • A JSON object maps directly onto a Python dict: json.dump writes it, json.load reads it back with types intact.
  • JSON is the standard text format for structured data, and what almost every API speaks.
