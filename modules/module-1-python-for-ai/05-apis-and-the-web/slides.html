Think of it as Ordering at a counter: you hand over a slip (the request), you get back a tray (the response).

HTTPEndpoints and JSON

A REST API is a set of named URLs (endpoints) you send requests to.

  • The response usually comes back as JSON.
  • From previous classes, JSON is just a dict in text form, so you already know how to read it.

requestsA GET request

import requests

resp = requests.get("https://api.example.com/facts")
data = resp.json()      # JSON -> dict
print(data["fact"])
  • requests.get(url) fetches from an endpoint.
  • .json() parses the response body into a dict.
  • Pull out the field you need by key.

requestsAlways check the status

resp = requests.get(url)
if resp.status_code == 200:
    data = resp.json()
else:
    print("request failed:", resp.status_code)
Do not assume success A call can fail: a wrong URL, a service down, a bad key. 200 means OK. Check the status before you trust the body.

requestsA POST with a JSON body

resp = requests.post(
    "https://api.example.com/ask",
    json={"question": "hello?"},
)
print(resp.json())
  • requests.post(url, json=...) sends data in the request body.
  • This is the exact shape of an LLM call: a prompt goes in, a reply comes back.

What an LLM isAn honest black box, for now

An LLM is a program trained on a very large amount of text that predicts plausible next text. Today we use it as a black box: text in, text out.

A promise In Module 3 we open the box and see exactly how it works. For now, calling it is just another request and response.

LocalYour first call, with Ollama

import requests

resp = requests.post(
    "http://localhost:11434/api/generate",
    json={"model": "llama3.2",
          "prompt": "Say hello.",
          "stream": False},
)
print(resp.json()["response"])
  • Ollama runs a small model on your own machine.
  • No token cost, and your text never leaves your laptop.
  • Same request-and-response shape you just learned.

Mental modelIt generates, it does not search

Common misconception The model is not looking things up on the internet. It generates text from patterns it learned during training. That distinction matters later: giving it real documents to read is RAG, in Module 4.

HostedThe same prompt, on Groq

import os, requests

resp = requests.post(
    "https://api.groq.com/openai/v1/chat/completions",
    headers={"Authorization": f"Bearer {os.environ['GROQ_API_KEY']}"},
    json={"model": "llama-3.1-8b-instant",
          "messages": [{"role": "user", "content": "Say hello."}]},
)
print(resp.json()["choices"][0]["message"]["content"])
  • Groq runs bigger open models on someone else's hardware.
  • Faster than a laptop, with a free tier.

HostedThe API-key habit

A hosted call needs a free key. Where the key goes matters.

Never in the code Put the key in an environment variable and read it with os.environ. Never paste it into code and never commit it. Remember from 1.1: the repo keeps history, so a key pushed once stays in that history.

Two ways to reach a modelLocal and hosted

Local (Ollama)
  • Private: text stays on your machine
  • Free, no key
  • Limited by your hardware
Hosted (Groq)
  • Fast, bigger open models
  • Free tier, needs a key
  • Runs on someone else's hardware
