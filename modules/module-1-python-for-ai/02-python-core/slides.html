Strings · 1 of 3Reshape text: case, trim, slice

s = "  Data Science  "
print(s.strip())          # "Data Science"
print(s.strip().upper())  # "DATA SCIENCE"
print("ada".title())      # "Ada"

text = "python"
print(text[0], text[-1])  # p n
print(text[::-1])         # nohtyp
print(len(text))          # 6
  • .lower(), .upper(), .title() change case.
  • .strip() trims whitespace from the ends.
  • Index and slice like a list: s[0], s[-1], s[:3], s[::-1].
Strings are immutable Every method returns a new string; the original never changes. Keep the result by assigning it.

Strings · 2 of 3Split, join, replace

csv = "ada,alan,grace"
parts = csv.split(",")
print(parts)              # ['ada', 'alan', 'grace']

print(" | ".join(parts))  # "ada | alan | grace"

print("cat and dog".replace("and", "or"))
# "cat or dog"
  • .split(sep) turns a string into a list of parts.
  • sep.join(list) turns a list of strings back into one string.
  • .replace(old, new) swaps every occurrence.
RememberSplit and join are opposites: text to list, list to text.

Strings · 3 of 3Search, test, and format

email = "ada@site.com"
print("@" in email)             # True
print(email.startswith("ada"))  # True
print(email.find("@"))          # 3
print("banana".count("a"))      # 3
print("2024".isdigit())         # True

print(f"{3.14159:.2f}")         # 3.14
  • in, .startswith(), .endswith() test for substrings.
  • .find() gives a position; .count() counts occurrences.
  • .isdigit(), .isalpha() check the content.
  • f-strings format too: f"{price:.2f}", alignment f"{name:>10}".

Reading inputinput() reads a line, always as text

age = input("Your age? ")   # user types 42
print(type(age))            # <class 'str'>
print(age + 1)              # TypeError: str + int

age = int(age)              # convert first
print(age + 1)              # 43

# convert on the way in
price = float(input("Price? "))
  • input(prompt) pauses the program, waits for Enter, and hands back the whole line the user typed.
  • The prompt is optional but tells the user what to enter.
Always a string Even if the user types 42, you get the text "42". Convert with int(...) or float(...) before any math, or values will concatenate or raise a TypeError.

Data structures · tuplesTuples: fixed records

color = (255, 128, 0)     # an ordered, fixed record
r, g, b = color           # unpack into variables
print(r, g, b)            # 255 128 0
print(color[0])           # 255

print(color.count(0))     # 1
print(color.index(128))   # 1

# color[0] = 99           # TypeError: cannot change
  • Ordered like a list, but immutable.
  • Great for a fixed record: an RGB color, a coordinate, a row.
  • Unpack straight into variables.
  • Only two methods, since it never changes: .count() and .index().
No insert, update, or delete A tuple is frozen once made. Need to change it? Use a list.

Data structures · dicts (1 of 2)Dicts: add, update, delete

stock = {"apple": 3, "banana": 5}
print(stock["apple"])     # 3   (access by key)

stock["cherry"] = 8       # insert a new key
stock["apple"] = 4        # update an existing key
del stock["banana"]       # delete a key
print(stock)              # {'apple': 4, 'cherry': 8}

print(stock.pop("apple")) # 4   (remove and return)
  • Look up a value by its key, not a position.
  • d[key] = value both inserts and updates.
  • del d[key] removes; d.pop(key) removes and hands the value back.

Data structures · dicts (2 of 2)Dicts: look inside safely

stock = {"apple": 4, "cherry": 8}

print("apple" in stock)      # True   (membership)
print(stock.get("pear", 0))  # 0      (default, no KeyError)

for item, qty in stock.items():
    print(item, qty)

stock.update({"pear": 2})    # merge in another dict
print(list(stock.keys()))    # ['apple', 'cherry', 'pear']
  • in tests for a key; .get(key, default) avoids a crash on a missing key.
  • .items(), .keys(), .values() loop over the contents.
  • .update() merges another dict in.
Think of it asA labeled filing cabinet: fetch, file, and refile by label.

Data structures · sets (1 of 2)Sets: unique items

langs = {"python", "sql"}
langs.add("rust")          # insert
langs.add("python")        # ignored: already there
langs.discard("sql")       # delete (no error if missing)

print("python" in langs)   # True   (fast membership)
print(len(langs))          # 2

print(set([1, 1, 2, 2, 3]))  # {1, 2, 3}  (dedupe)
  • An unordered collection of unique items.
  • .add() inserts; adding a duplicate does nothing.
  • .discard() and .remove() delete.
  • Wrapping a list in set(...) drops duplicates.

Data structures · sets (2 of 2)Set algebra: union, intersection, difference

frontend = {"html", "css", "js"}
backend  = {"python", "sql", "js"}

frontend | backend   # union: in either
frontend & backend   # intersection: in both -> {'js'}
frontend - backend   # difference: only in frontend
| union
& intersection
- difference

Comprehensions · listBuild a list in one line

celsius = [0, 20, 37, 100]

# map: transform every item
[c * 9/5 + 32 for c in celsius]
# [32.0, 68.0, 98.6, 212.0]

# filter: a trailing if keeps some
[c for c in celsius if c >= 20]     # [20, 37, 100]

# conditional expression: choose per item
["pass" if s >= 70 else "fail" for s in [55, 82, 70]]
# ['fail', 'pass', 'pass']
  • Map: an expression applied to each item.
  • Filter: a trailing if keeps only some items.
  • Conditional expression: a if cond else b at the front chooses the value per item.
Two different "if"s A trailing if filters. An if / else at the front chooses the value.

Comprehensions · dictBuild a dict in one line

names = ["Ada", "Alan", "Grace"]

# key: value for each item
{name: name[0] for name in names}
# {'Ada': 'A', 'Alan': 'A', 'Grace': 'G'}

# filter while building
{n: len(n) for n in names if len(n) <= 4}
# {'Ada': 3, 'Alan': 4}
  • Same shape as a list comprehension, but you write key: value.
  • Great for turning a list into a fast lookup table.
  • A trailing if filters here too.

ComprehensionsKeep them readable

Comprehensions should make code clearer, not denser.

Rule of thumb If you cannot read it aloud in one breath, use a plain loop instead. A comprehension that needs a second read is doing too much.

FunctionsA function is a reusable machine

Inputs go in, work happens, a result comes out.

  • The inputs are parameters.
  • The result is handed back with return.
  • Define it once, then call it as many times as you like.
Think of it as A coffee machine: beans and water in, coffee out. You do not rebuild it each morning; you just use it again.

FunctionsParameters, return, and defaults

def area(width, height):
    return width * height

print(area(3, 4))            # 12

def greet(name, greeting="Hello"):  # default after non-default
    return f"{greeting}, {name}"

print(greet("Ada"))          # Hello, Ada
print(greet("Alan", "Hi"))   # Hi, Alan
  • Parameters name the inputs.
  • return sends a value back to the caller.
  • A default is used when you leave that argument out.
Defaults come last Parameters with defaults must follow those without. def f(a, b=1) is fine; def f(a=1, b) is a SyntaxError, since Python could not tell which argument you meant.

Functionsprint shows, return gives back

def add_shout(a, b):
    print(a + b)        # shows it, returns None

result = add_shout(2, 3)   # prints 5
print(result)              # None
The classic mix-up print is for a human to read. return hands a value back to the program. If a function only prints, the caller gets None and cannot build on the result.

FunctionsAny number of arguments: *args and **kwargs

def total(*args):        # extra positionals -> tuple
    return sum(args)

print(total(2, 4, 6))          # 12
print(total(1, 2, 3, 4, 5))    # 15

def tag(name, **kwargs):  # extra keywords -> dict
    return name, kwargs

print(tag("div", id="main", cls="box"))
# ('div', {'id': 'main', 'cls': 'box'})
  • *args gathers any extra positional arguments into a tuple.
  • **kwargs gathers any extra keyword arguments into a dict.
  • The names are convention; the * and ** do the work.
Where you will meet it Functions that accept "anything extra" use this. You will pass **kwargs straight through to model and API calls later in the course.

Type hintsNotes about what goes in and out

def greet(name: str) -> str:
    return f"Hello, {name}"

# hints do not run or convert anything
greet(123)   # still runs; the editor just warns
Why now Type hints document what a function expects and returns, and let your editor catch mistakes. They do not change behavior. We seed the habit early because Pydantic (4.3) and tool schemas (Module 5) lean on it.
