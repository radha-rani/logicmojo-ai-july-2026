TensorsA NumPy array with two superpowers

import torch

t = torch.tensor([[1., 2., 3.],
                  [4., 5., 6.]])
print(t.shape)     # torch.Size([2, 3])
print(t.dtype)     # torch.float32
print(t + 10)      # elementwise, like NumPy
The one ideaEverything in PyTorch flows as tensors. The array skills from class 1.4 (The data stack) carry straight over.

TensorsThe NumPy fundamentals still hold

x = torch.tensor([1., 2., 3.])
print(x.mean())            # tensor(2.)
print(x * 2)               # [2., 4., 6.]

bias = torch.tensor([10., 20., 30.])
batch = torch.ones(2, 3)
print(batch + bias)        # broadcast across rows
  • Shape, indexing, slicing, and broadcasting work as in class 1.4 (The data stack).
  • Move data with .to(device) to run on a GPU.
  • Convert when you need to: t.numpy() and torch.from_numpy(a).

AutogradGradients for free

x = torch.tensor([1., 2., 3.], requires_grad=True)
y = (x ** 2).sum()      # y = 1 + 4 + 9 = 14

y.backward()            # record then differentiate
print(x.grad)           # tensor([2., 4., 6.])  =  2*x
  • PyTorch records every operation on a tracked tensor.
  • Calling .backward() on the loss computes the gradient with respect to every parameter.
  • In class 2.3 (Neural networks) you did this by hand; here one call does it.

AutogradIt records a graph, then differentiates it

Forward (blue) builds \( y \) from \( x \). Then .backward() walks the same graph in reverse (orange), applying the chain rule to fill x.grad, the same backprop you did by hand in class 2.3 (Neural networks), automated.

Why x.grad is [2, 4, 6]
  • Forward, square each input: \( [1,2,3] \rightarrow [1,4,9] \).
  • Sum them: \( 1+4+9 = 14 = y \).
  • So \( y = x_1^2 + x_2^2 + x_3^2 \).
  • Differentiate: \( \dfrac{\partial y}{\partial x_i} = 2x_i \).
  • At \( x=[1,2,3] \): \( 2x = [2,4,6] \), exactly x.grad.

AutogradThat .grad is the gradient from class 2.2 (How models learn)

The number in x.grad is exactly the \( \nabla_\theta L \) from the class 2.2 (How models learn) update rule.

It computes gradients; you write the loopPyTorch does not learn on its own. It hands you the gradient; you still apply the step, which is what the optimizer does next.

LossesPick the loss to match the task

import torch.nn as nn

mse = nn.MSELoss()              # regression (a number)
ce  = nn.CrossEntropyLoss()     # classification (a class)
  • MSELoss for regression, the mean squared error from class 2.2 (How models learn).
  • CrossEntropyLoss for classification, the cross-entropy from class 2.3 (Neural networks).
  • This is the output-layer table from class 2.3 (Neural networks), in code.
Key detailCrossEntropyLoss takes raw logits and the integer class index, and applies softmax internally.

LossesThe double-softmax trap

The model's last layer outputs logits, raw scores. CrossEntropyLoss applies softmax internally, so if you softmax first it happens twice and the signal washes out. Same logits \( (2, 1, 0) \), both ways:

Wrong: softmax twice
  • Your softmax: \( (2,1,0) \rightarrow (0.66,\ 0.24,\ 0.09) \).
  • Loss softmaxes again: \( \rightarrow (0.45,\ 0.30,\ 0.25) \).
  • The peak flattens, so the gradient weakens and training stalls.
Right: softmax once
  • Pass raw logits \( (2,1,0) \) straight to the loss.
  • It softmaxes once: \( \rightarrow (0.66,\ 0.24,\ 0.09) \).
  • A sharp target, so the gradient is strong and training moves.
The fixPass raw logits straight to CrossEntropyLoss and let it do the softmax once. Only apply softmax yourself at inference, when you actually want probabilities to read.

OptimizersThe object that takes the step

opt = torch.optim.SGD(model.parameters(), lr=0.1)
# or, the common default:
opt = torch.optim.Adam(model.parameters(), lr=0.01)
  • The optimizer applies the update rule to every parameter.
  • SGD is the plain step from class 2.2 (How models learn).
  • Adam adapts the step size per parameter and is the usual default.
  • You hand it the model's parameters and a learning rate.

nn.ModuleA container for layers and parameters

import torch.nn as nn

class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(64, 32)
        self.fc2 = nn.Linear(32, 10)
    def forward(self, x):
        x = torch.relu(self.fc1(x))
        return self.fc2(x)          # raw logits
  • nn.Module holds your layers and their parameters.
  • forward is the forward pass from class 2.3 (Neural networks).
  • Return raw logits; the loss handles softmax.
  • nn.Linear(64, 32) is a full layer: its weights and biases are created for you.

The loopFive moves, straight from class 2.2 (How models learn)

pred = model(x)               # 1. predict (forward)
loss = loss_fn(pred, y)       # 2. measure wrongness
opt.zero_grad()               # 3. clear old gradients
loss.backward()               # 4. compute gradients (autograd)
opt.step()                    # 5. take the downhill step

Modestrain() and eval()

Some layers behave differently while training versus scoring. A mode switch tells the model which.

  • model.train() before the training loop.
  • model.eval() before scoring, together with torch.no_grad().
  • Matters for dropout and batch norm, which we meet in class 2.5 (Training in practice).

The classic bugForgetting zero_grad

PyTorch accumulates gradients by default: each .backward() adds to .grad instead of replacing it.

The fixCall optimizer.zero_grad() every step, before .backward(). Skip it and last step's gradient contaminates this one, and training quietly breaks.
