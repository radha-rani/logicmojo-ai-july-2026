BatchingFeed the model small groups

Real datasets do not fit in memory at once, and one example at a time is noisy. We feed small groups called batches, handed out one at a time until the data is used up.

Batch size is a real knobBigger batches are steadier but need more memory; smaller ones are noisier but lighter. It trades memory, speed, and stability.

BatchingA DataLoader hands out batches

from torch.utils.data import TensorDataset, DataLoader

ds = TensorDataset(X, y)
loader = DataLoader(ds, batch_size=32, shuffle=True)

for xb, yb in loader:
    print(xb.shape)     # torch.Size([32, ...])
    break
  • Wrap tensors in a TensorDataset.
  • A DataLoader yields shuffled batches.
  • You loop over it instead of the whole dataset at once.
  • Shuffling each epoch keeps the model from learning the order.

EpochsOne pass, repeated

One epoch is one full sweep over the training data, batch by batch. You usually run several.

Think of it asRe-reading a textbook. One pass rarely sticks; a few passes settle the material. Too many, though, and you start memorizing the exact words rather than the ideas, which is overfitting.

EvaluationScore with learning turned off

model.eval()
with torch.no_grad():
    preds = model(X_val)
    acc = (preds.argmax(1) == y_val).float().mean()
model.train()
  • model.eval() switches layers like dropout to scoring mode.
  • torch.no_grad() skips gradient tracking: faster, and no accidental learning.
  • This is the generalization check from class 2.1 (What is machine learning), in code.

Learning curvesPlot train and validation loss

Record both each epoch. While both fall, the model is learning. That is the class 2.1 (What is machine learning) gap, watched live.

Learning curvesRead the moment it turns

When validation loss turns up while training loss keeps falling, overfitting has started.

The signalThe gap between the two curves widening is the tell. The best model is the one from the epoch where validation loss was lowest, not the last epoch.

StabilityBatch normalization steadies training

As training shifts the weights, the numbers flowing into each layer drift in scale, which slows learning. Batch normalization re-centers each layer's pre-activations across the batch, then rescales them with two learned numbers.

The formula, decoded

$$ \hat{x} = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}}, \qquad y = \gamma\,\hat{x} + \beta $$

  • \( \mu,\ \sigma^2 \): the mean and variance of \( x \) over the current batch.
  • \( \hat{x} \): \( x \) recentered to mean 0, variance 1.
  • \( \epsilon \): a tiny constant so the divide is never by zero.
  • \( \gamma,\ \beta \): a learned scale and shift, so the layer can undo the normalization if that helps.
Why it helps, and the mode switchCentered inputs let you train faster and at a higher learning rate, with a mild regularizing effect. In PyTorch it is nn.BatchNorm1d(width). Like dropout, it behaves differently in train() (batch statistics) and eval() (running averages), which is the other reason you switch modes.

ControlThree ways to hold overfitting back

Early stopping

Keep the model from the epoch with the best validation loss, not the last.

Weight decay

A gentle penalty on large weights (the optimizer's weight_decay) that discourages memorizing.

Dropout

In training, zero each activation with probability p (often 0.2 to 0.5) so no single path is leaned on.

Why the mode switch mattersIn train() dropout zeroes activations (here p = 0.5); in eval() it is off, so every neuron contributes at scoring time. That is why you call model.eval() first.
Batch norm and dropout together?Both fight overfitting, so it is tempting to stack them, but they can interfere. Batch norm measures the mean and variance of a layer's activations; dropout randomly zeroes some of those activations, which changes that variance during training. At scoring time dropout switches off, so the numbers no longer match what batch norm expected. The safe rule: reach for one first. Networks with batch norm often need little or no dropout. If you want both, place dropout after the batch-norm layer, never before it.

HardwareRun on a GPU when there is one

device = "cuda" if torch.cuda.is_available() else "cpu"
model = model.to(device)
xb = xb.to(device)
  • torch.cuda.is_available() checks for a GPU.
  • .to(device) moves the model and the data there.
  • Default path for this course: Colab's free T4. A local NVIDIA setup is an optional aside; no one is blocked without a GPU.

HardwareThe same-device trap

Every tensor in an operation must live on the same device. Move the model to the GPU but leave the batch on the CPU and PyTorch stops with an error.

model = model.to("cuda")   # model on GPU
pred  = model(xb)          # xb still on CPU
# RuntimeError: Expected all tensors to be
# on the same device

# Fix: move each batch too, inside the loop
for xb, yb in loader:
    xb, yb = xb.to(device), yb.to(device)
The fixSend every batch to the device inside the loop, not just the model once at the start.

ReproducibilityFix the seed

torch.manual_seed(0)
# now weight init and shuffling repeat run to run
  • Training uses randomness: weight initialization, batch shuffling.
  • A fixed seed makes a run repeatable, so a result you got yesterday returns today.
  • Essential when you are comparing two changes.

PersistenceSave and reload the weights

torch.save(model.state_dict(), "model.pt")

fresh = Net()
fresh.load_state_dict(torch.load("model.pt"))
fresh.eval()
What state_dict holdsThe learned numbers: every weight and bias. Save it so you do not retrain each time, then load it into a model of the same shape to reuse.

Persistencestate_dict saves numbers, not code

Saving the state dict does not save the model class.

The gotchaYou still need the Net definition in your code to load the numbers into. Keep the class and the weights together.

The bridgeInner layers are a learned representation

The numbers a trained network produces in its inner layers are a representation: a vector that captures something meaningful about the input.

Where this goesMeaning as a vector is exactly what powers embeddings and NLP in Module 3 (NLP to Transformers). You have now built the machine that produces them.

BuildA full train, validate, and save

In the notebook you train on the digits with a DataLoader, track training and validation loss, plot both curves, stop at the best validation epoch, run a GPU pass when one is available, report an honest test accuracy, and save the model with its state dict.

The habit to buildSplit three ways, watch the curves, keep the best epoch, and report the test number only once.
