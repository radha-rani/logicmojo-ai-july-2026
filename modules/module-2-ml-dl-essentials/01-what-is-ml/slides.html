The core flipYou write rules, or you learn them

Traditional code
  • You write the rules by hand.
  • if amount > 10000: flag()
  • Every case is one you thought of.
  • Breaks the moment the world shifts.
Machine learning
  • You supply labeled examples.
  • The algorithm finds the rule itself.
  • It covers cases you never enumerated.
  • It adapts as you feed it more data.
When to reach for ML Use it when the rule is too complex or too fuzzy to write out: recognizing a cat, flagging a fraudulent card swipe, ranking search results, estimating a house price. If a short if-statement would do the job, write the if-statement.

The core flipA spam filter, built both ways

Hand-written rules
def is_spam(email):
    if "free money" in email:  return True
    if "you won" in email:     return True
    if email.count("!") > 5:   return True
    return False
# misses "fr33 m0ney"; flags a real "you won the grant"
Learned from examples
  • Collect thousands of emails, each labeled spam or not.
  • The model finds the pattern across all of them.
  • New tricks like fr33 m0ney are caught once similar examples appear.
The real shiftYou stop editing a growing pile of if-statements and start curating examples. Gmail's spam filter is trained this way, not hand-coded, which is why it keeps working as spammers change tactics.

The landscapeThree kinds of machine learning

Supervised
  • Learn from labeled examples: each input carries the right answer.
  • Predict a house price from its features.
  • Real: Zillow's Zestimate, a bank's credit score.
Unsupervised
  • No labels. Find structure and groups in the data itself.
  • Group customers by behavior, with no target given.
  • Real: Netflix taste clusters, retail customer segments.
Reinforcement
  • Learn by trial and reward: act, get feedback, improve.
  • Master a game by playing it many times.
  • Real: DeepMind's AlphaGo, robot locomotion.
Where this course lives Almost everything ahead is supervised learning. It is also how language models are trained, at a vastly larger scale: predict the next token, with the true next token as the label. Reinforcement returns much later, when we shape how models behave.

The landscapeUnsupervised: structure without labels

Nobody says which group a point belongs to. The algorithm proposes the groups from the data, and you interpret them afterward.

  • A telecom firm feeds in usage data and gets back segments: heavy streamers, weekend callers, dormant lines.
  • The segments were never labeled. The model found them, then the team names and targets them.
  • Real: customer segmentation for offers, and the "customers who bought this" engines behind Amazon and Netflix.

From here on, every example is supervised: inputs paired with a known answer.

Supervised learningFeatures go in, a label comes out

Every example is a pair: the inputs, and the answer they should produce.

  • Features (X): the inputs the model sees.
  • Label (y): the answer it should produce.
  • Training means finding a mapping from X to y that also holds for pairs it has not seen.
Think of it as A trainee estate agent in their first month. They walk through thousands of past sales, each home's details and the price it fetched, and slowly build an instinct for pricing. Nobody hands them a formula. They absorb it from labeled examples until they can price a new listing on sight.

Two task typesThe label is a number, or a category

Regression: a number
  • House price, tomorrow's temperature, a ride's arrival time.
  • The label is continuous: it can land anywhere on a scale.
  • Real: Zillow's Zestimate, Uber and Ola fare and ETA.
Classification: a category
  • Spam or not, which digit, which disease.
  • The label is one of a fixed set of choices.
  • Real: Gmail spam filter, card fraud flags.
Same setup, different answer shape Both learn a mapping from features to a label. Only the label changes: a number for regression, a class for classification. The next three slides take each in turn.

Task type 1Regression: fit a line, read a number off it

  • The model fits a line (or curve) through the examples.
  • To predict, you read the line at the new input's position.
  • An example's error is its vertical distance from the line. Training pushes the total distance down.
Where you have seen itZillow's Zestimate reads a price off features of your home. A credit score and an NBFC's loan pricing are the same idea: a number learned from past cases. How the line is actually found is class 2.2 (How models learn).

Task type 2Binary classification: one of two classes

  • The model learns a boundary that separates the two classes.
  • It usually outputs a probability, then a threshold (often 0.5) turns it into a decision.
  • Move the threshold to trade caution against coverage: flag more, or flag only the sure cases.
Where you have seen itSpam or not, a card swipe legit or fraud, a loan likely to repay or default. Today's notebook is exactly this: a tumor benign or malignant.

Task type 3Multiclass: one of many categories

  • Now there are more than two classes: 10 digits, 3 iris species, dozens of product categories.
  • The model produces a score for every class and picks the highest.
  • Those scores are turned into probabilities that sum to one. The recipe is called softmax, decoded in class 2.4 (PyTorch fundamentals).
Where you have seen itReading handwritten digits on posted mail, sorting a photo into a species, routing a product to its category on Amazon. The notebook in class 2.4 (PyTorch fundamentals) classifies handwritten digits, 0 through 9.

Judging a modelHow do we know it is any good?

Evaluation is one move: make predictions, compare each to the true answer, then collapse the gap into a single number.

Regression: how far off
  • Average the distance between prediction and truth.
  • Predict $355k, true $340k: off by $15k.
  • Lower is better; the units are dollars.
Classification: how often right
  • Count the fraction of predictions that match.
  • 92 correct out of 100: accuracy 0.92.
  • Higher is better; the scale is 0 to 1.
The question that comes nextA score is only as honest as the data it is measured on. That is what the following slides fix, and we sharpen these numbers again near the end.

GeneralizationThe point is data it has never seen

A model that only scores well on the examples it trained on is worthless. What matters is performance on new data.

The exam analogy Studying past papers is training. Score yourself on those same papers and you are just measuring memory. The real exam asks questions you have not seen, so we hold some data back to play that role and refuse to let the model study it.
The word for itGeneralization is how well the learned rule carries to unseen inputs. It is the only thing we actually care about.

GeneralizationSplit into train, validation, and test

Train

The model learns here. Usually the largest part.

Validation

You tune choices here (model size, settings) and watch for overfitting.

Test

Touched once, at the very end, for the final honest number.

Why three, not two If you keep tuning against the test set, it quietly becomes part of training and stops being honest. Validation absorbs the tuning so the test set stays untouched and can still surprise you.

A common split is roughly 70 percent train, 15 validation, 15 test, shuffled first so each part looks like the whole.

GeneralizationOnly the held-out score is honest

model.fit(X_train, y_train)

model.score(X_train, y_train)   # 0.99  flattering, it saw this
model.score(X_test,  y_test)    # 0.86  the number that counts
  • The training score is inflated: the model already saw those answers.
  • The test score estimates real-world performance on new inputs.
  • Report the test score, never the training score.
The gap is a signalA small gap is healthy. A wide gap, high on train and low on test, is the warning we unpack next.

The workflowThe machine learning process, end to end

Split the data once. Train on one part, tune against validation in a loop, and touch the test set only at the very end. The dashed arrows show which split feeds which step.

The two failure modesOverfitting: memorizing the answer key

An overfit model memorizes the training data, noise and all, instead of the underlying pattern.

The student who memorized the key Perfect on the exact practice questions, lost the moment the wording changes. It learned the answers, not the subject.
How to spot it
  • Training score high, test score clearly lower.
  • A wide train-to-test gap.
  • Validation error starts rising while training error keeps falling.
How to treat it
  • More data, a simpler model, or regularization.

The two failure modesUnderfitting: too simple to learn

An underfit model is too simple to capture the real pattern. It does poorly even on the data it trained on.

The student who barely studied Struggles on the practice questions and the exam alike. Nothing was memorized, but nothing was learned either.
How to spot it
  • Training score low, test score also low.
  • Little gap, but both numbers are bad.
  • The model plateaus early and cannot improve.
How to treat it
  • More capacity, better features, or longer training.

The two failure modesWhat they look like on the same data

Same points, three models. The straight line is too rigid, the wild curve is too eager, and the middle one is what we want.

The two failure modesDetecting it while you train

Training error keeps falling. Validation error falls, then turns up as the model starts memorizing. Stop near the turn.

Honest evaluationFirst, the transforms we apply to data

Raw features rarely go straight into a model. Three transforms show up almost every time, and each one is learned from the data.

Scale
  • Put features on one scale so size does not swamp bedrooms.
  • Subtract the mean, divide by the spread.
  • Learned: the mean and spread.
Encode
  • Turn text categories into numbers.
  • "red, green, blue" becomes columns of 0s and 1s.
  • Learned: the list of categories.
Impute
  • Fill missing values so rows are usable.
  • Replace a blank age with the column's median.
  • Learned: the fill value.
Hold this thoughtEach transform learns something (a mean, a category list, a median) from whatever data you fit it on. Fit it on the wrong data and you have a problem, which is the next slide.

Honest evaluationData leakage: the peek that lies

# WRONG: the scaler learns the mean from ALL rows,
#        so it has already seen the test data
X = scaler.fit_transform(X)
X_train, X_test = split(X)

# RIGHT: split first, fit the scaler on train only
X_train, X_test = split(X)
X_train = scaler.fit_transform(X_train)
X_test  = scaler.transform(X_test)
  • Leakage is any test information sneaking into training, often through a transform fit too early.
  • It inflates the score, then the model disappoints in production.
  • Rule: split first, then fit every transform on the train part alone and only apply it to the rest.

Honest evaluationQuantify quality: accuracy, precision, recall

Sort every prediction into four boxes, then three numbers fall out.

  • Accuracy: of all predictions, the fraction correct.
  • Precision: of the ones you flagged positive, how many really were. Punishes false alarms.
  • Recall: of the real positives, how many you caught. Punishes misses.
There is a tradeFlag everything and recall is perfect but precision collapses. The right balance depends on whether a miss or a false alarm costs more.

Honest evaluationWhy accuracy alone can flatter a lazy model

If 99.8 percent of card swipes are legitimate, a model that always says "legit" scores 99.8 percent accuracy and catches zero fraud.

What accuracy hides
  • It rewards guessing the majority class.
  • On rare events, the number looks great and the model is useless.
What recall exposes
  • "Always legit" has recall 0 on fraud: it caught none.
  • On imbalanced data, watch precision and recall, not accuracy.
Same lesson, real systemsFraud, disease screening, and spam are all rare-positive problems. The same metrics return in Module 4 (LLMs and GenAI): judging whether a retriever pulled the few relevant documents out of thousands, or whether an answer is faithful rather than made up, is the same rare-positive problem in disguise.
